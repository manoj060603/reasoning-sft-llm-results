# Student-guided teacher-generation experiment

This experiment tests the first recommendation in
[Gen-SSD](https://arxiv.org/abs/2604.02819): let the student select teacher
continuations during generation using the student's perplexity, then use the
verified trajectory as ordinary response-only SFT supervision.

The comparison is matched on 2,000 questions from the sealed, decontaminated
15K training set and starts both full-SFT
arms from the original Qwen2.5-3B-Instruct checkpoint. One arm uses the existing
approved solutions. The other uses solutions generated by
DeepSeek-R1-Distill-Qwen-7B with chunk-level low-PPL selection by the original
3B student. Both arms use 250 updates, effective batch eight, 4K cutoff,
learning rate 2e-6, seed 42, and the same LLaMA-Factory full-parameter trainer.

This is a compute-scaled adaptation, not an exact reproduction. The paper's
default uses 4K-token chunks, a 16/8/4 candidate schedule, and 16K maximum
generation. This run uses 1K-token chunks, a 4/2 schedule, and 4K maximum
generation so it fits the assignment's 4K training regime and one B200. Up to
three deterministic attempts are allowed per question. The source order is a
fixed hash order over at most 4,000 sealed questions; generation stops when
2,000 verified trajectories have been collected. Both arms then use those same
2,000 question identities, so the only arm-level difference is the target
solution. Every exported guided trajectory must pass the assignment symbolic
grader against the sealed boxed answer; the run aborts rather than silently
mixing failed guided traces into the treatment arm. Because teacher success
determines which sealed questions enter the matched comparison, this experiment
estimates the effect on teacher-solvable questions rather than on the entire
15K distribution.

Development uses the existing 200-question training-disjoint panel with the
official temperature .6, top-p .95, eight samples, and 32,768-token cap. The
guided arm advances to the untouched 200-question confirmation panel only if
its development pass@8 strictly exceeds the existing-target control and it adds
no more than 40 truncated samples. No public-suite or leaderboard claim follows
from this development experiment.

## Terminal result: job 1144570

The job failed after 17 minutes 31 seconds during generation attempt one. It
processed and atomically saved 240 questions; 96 had symbolically verified
correct teacher answers. The pinned teacher revision was
`916b56a44061fd5cd7d6a8fb632557ed4f724f60`.

The blocking issue was termination handling in `reasoning.gen_ssd`: vLLM
returned an active request whose candidate set contained only zero-token
`stop` completions after the selected prefix had already terminated. The code
discarded empty strings and then raised `teacher returned no continuation for
an active problem`. The engine shutdown message followed that exception; it
was not a model-training or out-of-memory failure. No 2,000-row dataset was
exported, neither full-SFT arm trained, and no development or confirmation
score exists. The 240 per-question receipts and complete log are preserved
under `results/arc-20261011-snapshot-2316/gen-ssd-partial`.

The implementation now treats an all-empty, all-`stop` candidate set as normal
trajectory termination and includes a regression test. Per the run monitor's
constraint, the failed GPU job was not restarted.
